# Frontend construction map: screen-by-screen executable behavior

All 10 approved images' original ultra-detailed specs are included in `../reference_ui_specs/`. Here this file provides wiring instructions, state, contracts and definition of done. Page IDs and actual UI section counts are not collapsed into generic reusable screens. Every interactive control has a handler, typed DTO, authorization and error state. Screens are responsive desktop-first and support light/dark mode without visual regressions.

## Screen 01 — Home / Overview
Sections: global shell/search/profile/theme; stadium hero and actions; featured reel preview; KPIs; recent match list; sample reel cards; platform capabilities; horizontal how-it-works. Primary CTA navigates to `/uploads/new` with draft project selection. Paste Link opens URL import with rights disclaimer, not an auto-scraper. KPIs originate from aggregated eligible assets/runs/jobs and carry `as_of`, time window, organization scope; no placeholder counts in production. Featured reel must be an authorized playable asset. Empty account shows onboarding without fictional trust partners. On sample action click navigate `/reels/{id}` or `/library?type=reel`; denied media displays rights status.

## Screen 02 — Upload & Ingest
Sections: optional match context; ingest options; Upload File / URL / Batch mode tabs; drag area; URL textbox; supported formats; recent uploads; metadata preview; progress pipeline; live preview strip. On drag input validate approximate size/extension client-side; server is authoritative. Client computes incremental checksum when feasible, requests upload session, uploads parts with abort/retry and resumes by session ID. On final chunk submit complete, transition from uploading to validating and only then to processing. URL import returns supported provider auth/rights state or failure. Metadata edits update source record with version. Notifications subscribe to run status. Cancel clears outstanding parts and worker cancellation request, not deleting unrelated assets.

## Screen 03 — AI Processing Pipeline
Sections: match/source metadata; high-level progress; stage cards; large live annotated processing preview; player/ball/team/event diagnostic tiles; processing log; GPU resource panel; frame progress timeline; output summary. Stage statuses from `pipeline_steps`; overall progress weighted by measured workload, no hard-coded step percentages. Log uses cursor, handles reconnect/deduplication. Live preview loads sampled **actual processed frames**, overlays linked to run, with watermark if provisional. Resource panel privileged ops endpoint, unavailable when metrics not accessible. ID match count described as confirmed or candidate, never conflated. Failed step shows bounded retry with diagnostic code.

## Screen 04 — Analysis Workspace
Sections: match-context left; tab modes; synchronized main player; overlay controls; full tracked-player right panel; selected player card; transport; event chips; player presence timeline; moments/clip controls. Overlay switch groups filter client draw layers, source tracks unchanged. Player checkbox selects track UUID and state management, not jersey number alone. Multi-selection group creates reel targets only after validation. Click bounding box opens track card and fetches candidates. Player presence bars derive observation intervals excluding offscreen gap. Timeline and actual video player align on `pts_us`; hovered marker loads nearby source frames. Clip creation inserts `reel_clip` via API with target provenance. Any network outage displays last-known data with stale badge.

## Screen 05 — Tactical Intelligence
Sections: team/phase selector; tab navigation; team formation pitch; metrics cards; synced video; pass network; possession/heat zones; pressing map; off-ball runs; comparative players. All data tied to explicit run, time window, quality gate and pitch calibration. Recalculate/refresh based on selected window; no independent frontend derived metrics without definition. Pitch diagrams convert meter coordinates using versioned transform; invalid calibration yields explanatory `NOT_MEASURED`. Synchronized video current PTS highlights corresponding tactical observation and vice versa. Comparison includes cohort definition and data coverage.

## Screen 06 — Reel Builder / Spotlight Composer
Sections: left stepper/player target; aspect ratio/reel info; hero reel preview; spotlight controls; target lock; overlays/branding; suggested moments; clip timeline; generate/save buttons. Choosing player sets verified track reference; if unresolved show review action. Preview compositor consumes same keyframe/effect contract as render worker and scales normalized bbox to crop. Sliders clamp validated config; changing sliders updates preview and debounced persisted draft, undo creates history. Suggested moment checkboxes create editable clip sequence with source-PTS boundaries. Generate checks all segments and rights and displays actionable blocked reasons. Repeated click uses idempotency key.

## Screen 07 — Clip Studio / Timeline Editor
Sections: title/tool commands; Media/Graphics/Audio/Templates bin; video preview; inspector; quick edit ribbon; ruler; video track; transitions; spotlight/effect tracks; lower thirds; captions; statistics; soundtrack; audio FX. Timeline items are immutable IDs and editable positions; actions apply command pattern with undo/redo, debounced optimistic autosave and version checks. Drag edges change source IN/OUT PTS (ripple mode explicit), not lossy per-frame approximations. Inspector changes selected item and previews at exact PTS. Audio thumbnails/waveforms derived from actual assets; source audio and licensed soundtrack separately controllable. Caption output requires actual speech/text source; do not generate arbitrary claims about the football action.

## Screen 08 — Player Report
Sections: navigation; identity/evidence profile; scoped metric cards; heatmap; event timeline; action map; peer comparisons; generated insights; scouting report and PDF/share actions. Each metric renders state, definition, numerator/denominator, unit, validity window and confidence where applicable. Heatmaps from calibrated pitch values only; alternative screen-space presence explicitly labeled. Insights cite metric/event and model version; no unsourced free text assertions. Player ID is canonical verified ID only; track UUID and jersey OCR are shown separately if unresolved. Report job pins input run/version and waits for QA. Export PDF includes evidence footnotes, unresolved data caveats and selected clip references.

## Screen 09 — Library / Project Center
Sections: tabs/counts; filters/saved searches; row selection table; collaborators; selected-item right details/preview; direct actions (edit, download, duplicate, send, open). Query scope is tenant and role, with cursor pagination and stable sort. Bulk actions require explicit authorization for each selected asset. Download first calls rights decision endpoint, never direct static public object URLs. Share link has expiry/password policy and audit. Duplicate creates a new project artifact reference with rights inheritance, not unlicensed copy of media. Empty/filter-empty states distinct.

## Screen 10 — Export & Delivery
Sections: export stepper; project summary; final preview; chapters; render settings; branding/report bundle; export queue; share link; collaboration/client note; render progress; download/delivery. Output preset maps to server-validated codec/profile resolutions, with actual capability negotiation. Preview only based on already rendered asset or labeled render draft. Queue events and stages come from render_jobs; reports separately tracked. `Ready` only after output artifact passes QC and export rights. Download grants are freshly authorized and short lived, share status is separate from rendering. Delivery requires deliberate user confirmation with recipient, territory and role constraints, and queued dispatcher re-checks rights.

## Shared accessibility and UX requirements
Keyboard focus order, command shortcuts that do not conflict with browser, ARIA labels and live processing announcements, sufficient contrast, reduced-motion toggle (disable rays animation as preferred), localization/formatting, touch-friendly tablet targets and virtualized lists for 22+ tracks or hundreds of assets. Canvas elements need accessible equivalent track list/table. Loading/retry status never blocks video controls unnecessarily. Design tokens are versioned; no real production API response replaced with hard-coded fake sample data.
